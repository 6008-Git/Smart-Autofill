# Smart Autofill · 半自动表单填写助手

轻量 Chrome / Edge Manifest V3 扩展。用户点击当前输入框，插件根据附近标签和属性推荐个人资料字段，用户选择后才填写。所有界面与逻辑使用 HTML、CSS、原生 JavaScript。

本插件不会上传任何个人资料。所有资料仅存储在本地浏览器的 `chrome.storage.local` 中。

## 本地安装

无需构建、无需启动服务。

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`。
2. 打开「开发者模式」或「开发人员模式」。
3. 点击「加载已解压的扩展程序」或「加载解压缩的扩展」。
4. 选择本 README 所在的 `smart-autofill` 文件夹（其中包含 `manifest.json`）。
5. 点击扩展图标 →「管理个人资料」→ 填写并保存资料。
6. 打开或刷新普通 HTTP / HTTPS 表单页面。

安装或重新加载扩展后，已有网页需要刷新，才能使用新的内容脚本。浏览器内部页面、扩展商店页面及本地 `file://` 页面不能使用本扩展。

## 使用方式

1. 点击需要填写的输入框，或用 Tab 聚焦输入框。没有弹出时，保持光标在输入框内，按 **Alt+Z** 手动唤起；不要求之前的点击事件被插件识别。
2. 浮窗展示前 5 个候选字段。第一项有识别分数时显示「推荐」，无匹配时显示「常用字段」。这是关键词排序，不是概率。
3. 点击某个字段，仅向当前输入框写入该字段内容。
4. 推荐不准确时，点击「请选择字段」，在级联菜单中按「资料分类 → 经历记录/子分类 → 字段」查找，再点击「填写所选字段」。
5. 填写完成、失焦、点击其他区域或按 Esc 后关闭浮窗。

没有内容的字段显示「暂无内容」，无法点击填写；资料读取失败会显示具体提示，不会把读取失败伪装成未填写。记录以学校/学历/专业、公司/职位/时间、亲属关系/姓名、证书/奖项/论文/项目名称等内容摘要显示，不使用「第 1 条」等编号。摘要最多 90 个字符，较长项两行截断；悬停标题和选中后的路径显示摘要，完整资料可在管理页查看。手机号、证件号、完整职责和备注不会放进菜单摘要。

级联菜单支持每列独立滚动、鼠标悬停/点击展开、中文字段名与英文键搜索。方向键上下移动同列选项，右键进入下一列、左键返回上一列，Enter 选择，Esc 关闭。选择末级字段不会立即填写，需要点击确认；推荐按钮仍然点击即填写当前字段。收起时保持 224px 紧凑浮窗，展开后显示三列，并根据视口限制宽高。

浮窗右上角显示代码版本。更新到 0.3.3 后必须刷新已经打开的招聘网页，使页面中的内容脚本同步更新；仅重新打开资料管理页不能替换网页里已经注入的旧脚本。

## 功能

- 支持 `input` 的 `text`、`tel`、`email`、`number` 类型及 `textarea`。
- 使用 `label`、`placeholder`、`name`、`id`、`autocomplete`、`aria-label`、`title`、附近文本和输入类型加权识别当前字段。
- 每个来源只加一次权重；同分时优先更具体的关键词。附近文本最多向上 2 层，最多 200 字符和 80 个遍历节点，跳过输入值和脚本文本。
- 使用原生 value setter，绕过框架在元素实例上设置的 setter，触发冒泡的 `input`、`change` 事件并保持焦点。这是 React 受控输入框及 Vue 事件绑定所需的兼容机制。
- 密码框、只读框、禁用框、下拉框及其他不支持类型直接忽略。
- 下拉框始终由用户自己选择：原生 select、带 datalist 的输入框，以及通过 combobox、aria-haspopup、aria-expanded、候选列表关联或「请选择」占位文字声明的自定义下拉输入框均不触发浮窗，也不会填写。
- 数字框拒绝非数字内容时保留原值，并提示用户选择其他字段。
- Options 资料维护、Popup 快捷入口、JSON 导入和导出。
- 网站脚本调用 `focus()` 或模拟点击候选按钮不会触发填写。
- Alt+Z 直接对当前可填写输入框打开菜单；不会自动填写。使用捕获阶段监听减少网页阻止事件冒泡带来的漏触发。下拉框、密码框、只读框和禁用框继续排除；无输入框焦点时不接管快捷键。
- 内容脚本注入匹配 HTTP/HTTPS 的 iframe 及其 about:blank/srcdoc 子框架；支持开放 Shadow DOM 中的原生输入框，仍只处理当前字段。

保留原 MVP 的 23 个常用字段：

| 分类 | 字段 |
| --- | --- |
| 基本信息 | 姓名、手机号、邮箱、性别、出生日期、身份证号、民族 |
| 教育信息 | 学校、学院、专业、学历、学位、入学时间、毕业时间 |
| 地址信息 | 籍贯、省份、现居城市、详细地址、邮编 |
| 求职信息 | 当前单位、当前岗位、期望岗位、期望城市 |

日期、身份证号、手机号、邮编等均按文本保存，以保留前导零与用户指定格式。

0.2.0 根据用户提供的 11 类简历 JSON 增加了完整资料结构，共 140 项字段定义：基本信息、常用教育信息、地址信息、求职意向、教育经历、工作与实习经历、家庭情况、荣誉证书、获奖情况、论文、项目经历、专业技能、自我评价。包含紧急联系人、投递记录、各类来源和备注。

0.2.1 修复完整资料已导入、常用字段却显示空白的问题。导入预览按分类显示明细，读取已保存资料或确认导入后自动展开有内容的分类，导航与分类标题显示可用字段及记录数量。Popup 学校和浮窗的常用字段也使用同一套来源读取规则。

0.3.0 将浮窗的长下拉列表替换为级联选择器，并修正页面脚本的缓存读取：每次用户打开浮窗及确认填写时都重新读取已保存资料；用请求序号阻止晚返回的旧响应覆盖新导入数据；扩展上下文失效时提示刷新网页。同一页面重复初始化时先移除原监听器。没有更改 storage 结构，已成功保存的资料无需重新导入。

0.3.1 增加 Alt+Z 手动唤起，补齐 iframe 与开放 Shadow DOM 输入框的触发，改用捕获阶段监听点击、焦点和键盘事件。快捷键沿用相同下拉框排除规则，必须由用户选择资料后才填写。不增加权限，也不改变已保存资料。

0.3.2 将级联记录、推荐项、默认来源提示与管理页标题统一为内容摘要，管理页编辑名称等内容时标题同步更新。可按摘要中的公司/学校名称搜索。仅显示摘要，不修改原始记录、存储结构或填写值；新建空记录提示「待补充名称」。

0.3.3 整理明确的表单来源标记：例如「网页开发（信息3表单）；某表单填「区块链」」用于填写的值为「网页开发；区块链」。原文移入维护备注或数据来源，这些元数据和待补充项不进入填写候选。单值字段若出现互相矛盾的来源则保持为空，需要人工确认；「软件设计师（中级）」等真实限定信息保留。高中经历可独立维护与选择，不会覆盖最近的大学经历。

常用教育字段为空时，读取开始时间最近的一条教育经历；同一条经历提供学校、学院、专业、学历和学位，入学/毕业日期仅从明确的起止时间提取，保留年月或年月日精度。无日期的记录按后面的有内容记录作为默认，字段缺失不会借用另一条经历拼接。当前单位/岗位仅读取有「至今」等在职标记且无离职原因的工作记录；期望岗位和城市读取相应的求职意向；省市仅从现居住地里明确写出的行政区名称读取。

自动读取的常用字段下方标明来源。单独编辑可以覆盖默认；清空后恢复来源默认。默认显示不会另存为过时的副本，因此修改或删除经历后可以继续读取正确来源，已有用户手动值不会被覆盖。所有原始记录仍保存在各自分类，可在浮窗中单独选择。

教育、工作、家庭成员、证书、奖项、论文、项目分成 7 类可增删的记录，浮窗中每个字段注明类别、内容摘要和字段名，选择后仍只填写当前输入框。长文本使用 textarea 维护；技能、职责、项目亮点等文本列表每行一项，填写网页时以换行连接。分类可折叠，顶部可跳转到相应分类。

本版本以原生 JavaScript MVP 为基础，按用户要求扩展资料结构、级联菜单和 Alt+Z 触发；自定义字段/关键词、网站学习与映射、contenteditable、网站黑名单、暂停仍未实现。下拉选择控件始终留给用户手动选择。日期组件、封闭 Shadow DOM、浏览器禁止注入的页面及未授权站点不能用快捷键绕过；跨域 iframe 仍需要扩展具有该框架站点的访问权限。

运行代码只包含字段定义，初始资料全部为空，不预装个人内容。英文键统一采用 camelCase；姓名、电话、邮箱、地址、单位等有标准 HTML autocomplete 语义的字段配有对应规则，其他简历字段使用英文键和关键词识别，并可手动选择。

不会整页扫描，不会自动填写、点击下一步、登录、提交或识别验证码。没有 React/Vue 等运行依赖、后端、数据库、AI 模型、远程 API、远程字体或统计上报。

## JSON 导入导出

「导出已保存资料」下载 `smart-autofill-profile.json`。尚未保存的表单修改不会包含在备份中。Chrome、Edge 和不同浏览器用户配置之间的本地存储互相独立，可通过 JSON 迁移。

支持导出格式：

```json
{
  "version": 2,
  "profile": {
    "basic": { "name": "张三", "phone": "13800000000", "email": "test@example.com" },
    "education": { "school": "示例大学" },
    "location": { "city": "示例城市" },
    "job": { "expectedPosition": "工程师" },
    "educationHistory": { "records": [{ "school": "示例大学", "major": "计算机" }] },
    "workExperience": { "records": [{ "company": "示例公司", "responsibilities": ["职责一", "职责二"] }] },
    "selfAssessment": { "summary": "第一段\n第二段" }
  }
}
```

也支持不带 `profile` 外层的分组格式，以及文档示例的扁平格式：

```json
{ "name": "张三", "phone": "13800000000", "email": "test@example.com" }
```

完整字段结构以 `data/resume-schema.js` 为准；英文与中文对照见仓库根目录 `doc/profile-field-mapping.json`。其中 `*` 表示任意记录下标，例如 `educationHistory.records.*.school`。映射文件只包含字段说明，不包含个人资料值。

导入文件最多 1 MB：文本字段最多 10000 字符；文本列表为字符串数组，最多 200 项，每项最多 10000 字符；每类经历最多 100 条。未知字段、类型错误、重复字段或不支持版本会被拒绝。支持旧版 version 1 和扁平的 23 个常用字段；新版导出使用 version 2。个人资料扩展后，已有旧版资料不会丢失。

导入先显示已解析字段数量。点击「确认替换资料」才写入存储；导入会替换全部资料，未提供的内置字段清空，也会替换尚未保存的表单修改。可先导出备份，或取消导入。

自己的导入文件请保存在仓库根目录 `personal-data/` 等私人目录，该目录已加入 `.gitignore`，不会随源码发布。插件不会自动读取本地文件，需要在管理页自行选择文件导入。公开结构示例位于 `examples/profile.demo.json`，全部使用虚构内容。数字转为文本、null 转为空字符串，多条记录与文本数组保留各自结构；空白的常用字段在显示与填写时读取已有来源。

## 数据安全与权限

扩展仅申请 `storage` 权限。内容脚本匹配 HTTP / HTTPS 网站，这是分析用户选中输入框所需的页面访问范围。Chrome 会据此显示网站访问提示。

资料不会通过消息发送给网站或后台；后台脚本仅处理「打开管理页」。没有任何联网代码或个人资料日志。JSON 备份是用户主动下载的本地文件，包含明文个人资料，请妥善保管。本地存储没有额外加密，不支持跨设备自动同步。

## 开发与验证

```text
manifest.json           MV3 入口与最小权限
background.js           仅打开 Options 页面
data/field-rules.js      字段定义与识别关键词
data/resume-schema.js    完整简历字段结构（不含个人值）
data/profile.js          资料结构、storage 与 JSON 校验
data/field-tree.js       分类、子分类、记录与字段的级联树
content/detector.js      当前字段采集与加权识别
content/filler.js        原生 setter 与事件
content/floating-menu.js 浮窗与手动纠错
content/content.js       用户焦点与菜单生命周期
styles/content.css      saf- 前缀隔离样式
popup/                  扩展图标快捷入口
options/                资料管理与 JSON 导入导出
```

修改文件后在扩展管理页重新加载扩展，并刷新测试网页。无需 npm install、打包或构建。Chrome 内容脚本使用隔离执行环境，参见 [Chrome 官方内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

仓库根目录包含独立验收工具（不随扩展加载，不是应用后端），需要 Node.js 22+：

```powershell
node --test tests/core.test.mjs tests/profile-schema.test.mjs tests/field-tree.test.mjs tests/content-lifecycle.test.mjs
node tests/browser-smoke.mjs chrome
node tests/browser-smoke.mjs edge
```

浏览器测试通过 DevTools Protocol 在独立临时配置中加载扩展，用拦截响应提供本地测试页面，不启用 HTTP 服务器，不使用 Playwright/Selenium。默认使用 Windows Chrome/Edge 标准安装路径，可在测试脚本的 `executables` 中调整。只使用虚构资料，不接触现有浏览器用户配置。测试完成会关闭测试浏览器、清理其临时配置；截图与测试备份保存在根目录 `artifacts/`，该目录已被 Git 忽略。

图标已包含，可使用 `python scripts/build-icons.py` 在仓库根目录重新生成。验收结果与框架测试边界见 `doc/acceptance.md`。

本地转换工具可以重新生成导入文件与字段映射，原文件不会修改：

```powershell
node scripts/convert-profile.mjs '你的信息JSON目录' '本项目/personal-data'
```

工具只输出文件数、字段数与覆盖验证结果，不打印个人内容。字段映射按源文件与中文键精确转换，遇到未映射字段会报错，避免静默丢失。
